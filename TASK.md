# Контекст и требования

Источник: обсуждение тестового задания с пользователем, 25–30 сентября 2026.

## Задание работодателя

Срок выполнения — пять дней. Создать минимальный интерфейс на React для отправки и получения **только текстовых сообщений** в MAX. Использовать GREEN-API, внешний вид чата ориентировать на `https://web.max.ru/`. Если MAX недоступен, работодатель допускает WhatsApp или Telegram; текущая реализация предназначена для MAX.

Обязательный сценарий:

1. Пользователь открывает сайт и вводит свои `idInstance`, `apiTokenInstance`.
2. Вводит телефон получателя и создаёт чат.
3. Отправляет текст в MAX через `SendMessage`.
4. Получатель отвечает из MAX.
5. Ответ появляется в соответствующей переписке через HTTP API: `ReceiveNotification`, затем `DeleteNotification`.

## Дополнительные пожелания пользователя

- Реализовать весь проект самостоятельно, не выдавать пошаговые задания пользователю.
- Небольшой проект с последовательным, понятным стилем, естественными именами и объяснимыми решениями.
- Минимальный набор функций, без необоснованного усложнения.
- Небольшие индивидуальные детали в формулировках, состояниях и поведении, сохраняя образец MAX.
- Сохранить требования вместе с работой.

## Принятые решения

- React + TypeScript + Vite. Язык не был задан работодателем; выбран TypeScript для описания сообщений, состояний и проверки API-границ.
- Тёмная тема, список чатов слева, сообщения справа; на узком экране — одна область за раз.
- Помимо двух ключей форма запрашивает `apiUrl` из кабинета: это обязательная часть адреса сервера GREEN-API.
- Инстанс подключается к аккаунту MAX через кабинет GREEN-API. Создание инстанса, QR и ввод 2FA в приложении не требуются для сценария задания.
- По номеру определяется настоящий `chatId`. Отправка и получение используют его, а не предполагают, что номер придёт во входящем уведомлении.
- Хранение истории в ТЗ не оговорено. История и черновики живут в памяти вкладки, прежняя история MAX не загружается.
- Один последовательный потребитель очереди; сообщение сначала попадает в состояние, потом подтверждается.
- Настройки меняются отдельным явным действием. `SetSettings` не вызывается на каждый вход.
- Успешный `SendMessage` означает постановку в очередь, не гарантированную доставку. Статусы показываются отдельно.
- Нет автоматического повторения неясной отправки и искусственных «человеческих ошибок» в коде.

## Что требует реального аккаунта

Проверка фактической доставки, CORS конкретного сервера и получения ответа с другого аккаунта MAX. Ключи и второй аккаунт пользователем не предоставлены, поэтому эти проверки не заявляются как выполненные.
